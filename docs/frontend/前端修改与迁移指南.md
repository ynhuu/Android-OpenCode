# 前端修改与迁移指南

本文面向前端维护者，说明基于官方 OpenCode **2.0.25** 的定制功能、补丁应用方法及后续版本迁移要求。安装和使用 Android 客户端请参阅 [README](../../README.md)。

本文描述的是仓库补丁，不代表已发布前端包含全部修改；发布版本及差异以 README 和 Release 页面为准。

## 补丁基线

- 官方源码：<https://github.com/anomalyco/opencode/archive/refs/tags/v2.0.25.zip>。
- 完整补丁：[前端修改与迁移指南.patch](./前端修改与迁移指南.patch)，包含相对官方 **2.0.25** 的 19 文件差异。
- 只应用完整补丁，不叠加旧的会话菜单补丁或主屏幕补充补丁。
- 下文源码路径均相对于解压后的 `opencode-2.0.25/` 根目录。

## 定制功能与迁移约束

以下各节分别列出功能行为、相关源码及迁移时必须保留的约束。迁移时应逐项核对，不要直接覆盖新版上游文件。

### 连接

- `packages/app/.env.production` 设置 `VITE_OPENCODE_SERVER_MODE=none`。
- 不自动添加或连接网页同源后端；保留用户已保存的连接，不修改连接业务逻辑。

### 文件页

- 切回文件页时刷新根目录和已展开子目录；初次进入、重新连接及可见期间工作目录变化也触发刷新。
- 无手动刷新按钮，不增加定时轮询；保留后端文件变化事件处理。
- 仅刷新目录列表，不关闭标签、不整页刷新、不强制重读已打开文件。
- 从文件列表重新打开文件时强制读取最新内容；切换已有标签或返回文件页仍使用缓存。

**源码位置**：`packages/gui-extensions/src/file/` 下的 `refresh.tsx`、`mobile.tsx`、`browser.tsx`、`sidebar.tsx`、`renderer.tsx`。

2.0.25 的移动文件页和终端入口位于「More…」菜单。回归测试应经该入口打开视图，不恢复旧版导航标签。

**迁移约束**：保留 `createFileTreeRefresh` 的可见性判断、递归 `tree.sync(path, { force: true })`，以及列表打开与标签切换的区别。

### 移动终端

- 仅在 Android、iOS、iPadOS 显示辅助键，不按屏幕宽度判断；桌面不显示。
- 单排横向滑动，隐藏滚动条，空间足够时居中。
- 保留 Esc／Tab／方向键、Ctrl、⌃C/D/L、Home／PgUp／PgDn／End；Ctrl 将下一次英文字母转换为控制字符，Home／End 遵循 application cursor 模式。
- 使用现有 Ghostty 和 PTY WebSocket，不改变后端协议。
- 终端画布支持单指上下滑动：将触摸位移累计后转为 Ghostty 已有的滚轮事件，普通模式查看历史输出，全屏程序沿用原有方向键输入处理；不将外层改为原生滚动容器。
- 移动端触摸按下不立即聚焦输入框，只有位移不超过 8 px 的单指轻点才聚焦。滑动不会主动弹出键盘，也不主动关闭已打开的键盘；桌面鼠标行为保留。

**源码位置**：`packages/gui-extensions/src/terminal/` 下的 `terminal.tsx`、`i18n/en.ts`。

**迁移约束**：

- 仅移动系统注册触摸监听；`touchmove` 使用非 passive 监听取消页面默认滚动。
- 多指、释放及取消时清除手势状态，终端卸载时移除监听；不影响辅助键横向滚动和桌面滚轮。
- 保留触摸位移的 33 px 累计取整，对应 Ghostty 全屏模式每次滚轮的方向键次数。
- 保留 8 px 轻点阈值及 capture 阶段对 Ghostty `touchend` 自动聚焦的拦截。不要改为在 `pointerdown` 立即聚焦，否则滑动会弹出键盘。

**回归用例**：`packages/app/e2e/regression/terminal-input.spec.ts`，覆盖上下滑动历史输出、连续小位移累计、全屏模式的 PTY 输入，以及滑动不获焦、轻点获焦。

### Android 键盘与消息滚动

- 消息区原本贴底时，键盘弹出／收起导致容器高度变化，继续保持最新消息位于输入框上方。
- 查看历史消息时保留阅读位置，不强制跳到底部。

**源码位置**：`packages/app/src/session/timeline/virtualizer.tsx`。

**迁移约束**：

- 仅针对 Android UA，在容器高度变化且原本跟随最新消息时调用 `scrollToEnd()`；不修改 iPhone／iPad 行为。
- 保留 `interactive-widget=resizes-content`，不要替换为输入框聚焦时无条件滚到底部。

### iOS 目录选择器

- 允许触摸滚动，清除未选中行残留的悬停高亮。

**源码位置**：`packages/app/src/workspaces/selection/dialog.tsx`、`patches/solid-prevent-scroll@0.1.11.patch`、`package.json`、`bun.lock`。

**迁移约束**：`solid-prevent-scroll@0.1.11` 使用 `event.composedPath()` 识别 Shadow DOM 内的事件目标；保留依赖补丁及其登记。

### 会话长按、重命名与删除

- 修复触摸长按菜单、重命名输入框和删除确认框的交互；普通 Safari 与主屏幕模式使用同一实现。

**源码位置**：`packages/app/src/home/sessions/view.tsx`。

**迁移约束**：

- 定时器和原生 `pointercancel`／`touchcancel` 后的 `contextmenu` 两条菜单打开路径均登记触摸手势。
- 通过 document capture 阶段的非 passive 监听器取消释放默认动作，拦截落回原会话行的兼容鼠标事件；保护期间外部焦点变化不关闭菜单。
- 新触摸、笔操作、菜单外鼠标操作或按键解除保护；释放或取消后最多保留 750 ms，随后移除监听器，避免永久拦截。
- 定位用的不可见 `Menu.Trigger` 设置 `inert`，避免 Kobalte 关闭菜单时强制聚焦 trigger，使重命名输入框失焦而被 `onBlur` 取消。实际键盘菜单入口仍是会话行按钮。
- 重命名、删除在点击或 Enter／Space 后显式关闭菜单并执行，不在菜单项 `pointerup` 时执行。
- 重命名在 Solid 事件批处理后的 microtask 聚焦并选中文本；保留 Enter 保存、Escape／真实失焦取消和 IME 处理。菜单关闭不能抢走输入框或删除确认框的焦点。

**回归用例**：`packages/app/e2e/regression/home.spec.ts`。

## 应用补丁与构建

### 准备环境

- Bun、Git。
- 能保留符号链接的解压工具。
- 官方 OpenCode 2.0.25 源码 ZIP，下载地址见「补丁基线」。

**只对全新解压目录应用补丁，不在已修改目录重复应用。** 下列 `/path/to/` 路径均为占位路径，执行前需替换。

### 应用补丁

以下命令从 Android 仓库根目录执行；源码包路径按本机位置调整：

```bash
export FRONTEND_PATCH="$PWD/docs/frontend/前端修改与迁移指南.patch"
unzip /path/to/opencode-v2.0.25.zip -d ../fresh-v2.0.25
cd ../fresh-v2.0.25/opencode-2.0.25
git apply --check "$FRONTEND_PATCH"
git apply "$FRONTEND_PATCH"
bun install --filter '@opencode/app' --filter '@opencode/storybook' --ignore-scripts
```

解压必须保留符号链接，尤其是 `packages/app/src/custom-elements.d.ts` 和 `packages/app/public/` 中的图标。若文件内容仅为 `../../...` 路径文本，应按 ZIP 中的链接信息恢复后再构建。

### 类型检查与构建

应用补丁后，从官方源码根目录执行：

```bash
cd packages/app
bun typecheck
VITE_OPENCODE_SERVER_MODE=none OPENCODE_CHANNEL=latest bun run build
```

构建产物位于 `packages/app/dist/`。不要将源码、依赖目录或补丁混入构建产物。

## 迁移到后续官方版本

### 迁移流程

1. 保留当前定制源码和完整补丁，将新官方源码解压到独立目录。
2. 在新目录执行 `git apply --check`。检查并逐项适配冲突，不整文件覆盖上游，不仅修改版本号。
3. 按「定制功能与迁移约束」逐项迁移。文件操作继续使用当前 `SessionScreen.file`；终端使用扩展上下文的 layout，保留上游生命周期、持久化与关闭逻辑。
4. 保留上游测试，补上定制行为的回归用例；不覆盖官方 review 源码或生成客户端。
5. 运行类型检查、正式构建和相关回归，并完成下方验收清单。会话代码修改前后比较生产构建基准。
6. 相对新版本官方源码重新生成一份完整补丁，不叠加历史补丁。用另一份全新解压源码应用该补丁，逐文件比对定制源码。
7. 更新本文的官方基线、修改位置、迁移要点及补丁摘要。迁移只涉及前端，不升级后端、不改变服务器配置、不重启服务。

### 验收清单

- [ ] 文件页刷新和文件读取符合预期，切换标签不强制重读文件。
- [ ] 移动终端辅助键、历史滑动、小位移累计及全屏模式 PTY 输入正常。
- [ ] 终端滑动不主动弹出键盘，单指轻点可聚焦；桌面鼠标和滚轮行为不变。
- [ ] Android 键盘弹出或收起时，贴底消息继续贴底，历史阅读位置不被强制改变。
- [ ] iOS 目录选择器可触摸滚动，无残留悬停高亮。
- [ ] 在普通 Safari 和主屏幕模式分别真机验证长按、重命名、软键盘与删除确认。
- [ ] 新完整补丁可应用于另一份全新官方源码，结果与定制源码逐文件一致。

以上是验收要求，不是已完成的验证记录。自动化事件模拟不能代替真机验收。

### 重新生成完整补丁

从 Android 仓库根目录使用 `tools/rebuild_frontend_patch.py`。它按参考补丁中列出的文件生成差异，新增修改文件需先纳入参考列表：

```bash
python3 tools/rebuild_frontend_patch.py \
  --source /path/to/custom-source \
  --official /path/to/official-source.zip \
  --files-from docs/frontend/前端修改与迁移指南.patch \
  --output /path/to/new-complete.patch
```

## 打包与发布

构建产物通过 Android 仓库的 `tools/package_update.py` 打包为 `dist.zip` 和更新清单。更新地址、版本规则和安全限制见 [README 的前端更新说明](../../README.md#前端更新)。

发布新前端时须递增前端版本代码；它与 APK 版本代码相互独立。不要将补丁应用成功或构建成功视为已发布，也不要在未经授权的情况下替换远程资源。
